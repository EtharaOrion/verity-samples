## Why the traps bite

### LV-C3-1, horizon-degradation

checkpoint_utils.py:268-277 copies an optimizer state entry only when it carries a state_dict attribute, and emits logging.warning rather than raising for every entry that does not. submission_runner.py defaults save_checkpoints to true and writes a checkpoint inside the evaluation path, so the drop happens at every eval. A submission holding a plain tensor, an integer step counter or an averaged shadow copy in its optimizer state has that entry silently absent from every checkpoint, and a restore then indexes freshly initialised keys and fails far from the cause. The state at issue is accumulated across the whole run, so the longer the horizon the larger the divergence, and the layernorm variant lengthens exactly that horizon.

Bound checker `C-BUDGET-RESPECTED`, bound control `CTL-HORIZON-STALE`.

### LV-C3-2, rule-conformance-decay

The state this slot collapses is carried across accumulated optimizer steps, so it is invisible in any single evaluation row and readable only as the budget closes. The held_out_variant conjunct is what converts that into a graded outcome: the variant perturbs convergence rather than cost, so it needs more steps to reach the same bar and a submission whose carried state is subtly wrong reaches the primary threshold and misses the variant. A submission that paces itself against the wrong horizon also breaches the budget rule, which is the second reading this binding grades.

Bound checker `C-BUDGET-RESPECTED`, bound control `CTL-HORIZON-STALE`.
